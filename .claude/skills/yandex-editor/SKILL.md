# Редактура текста агентом Яндекса (yandex-editor)

Скилл отправляет русский текст агенту в Яндексе и возвращает результат. Яндекс хорошо работает с русским языком. Агент умеет **и редактировать (вычитка), и писать статью по заданному скелету** — что именно он сделает, задаёт инструкция во входе.

Сам промпт агента задан **на стороне Яндекса** (`YANDEX_PROMPT_ID`); скилл передаёт текст и забирает результат через OpenAI-совместимый Responses API (`ai.api.cloud.yandex.net/v1`).

## Режимы

- **Вычитка (`--edit`)** — «только язык: грамматика, пунктуация, согласование, гладкость; не переписывай, не добавляй разделы, не меняй смысл». Минимальное вмешательство, текст почти не меняется. **По умолчанию для «вычитай / поправь язык».**
- **Коррекция (`--correct`)** — разрешает менять формулировки, порядок слов и структуру предложений, переписывать неудачные места ради ясности — **но сохраняет смысл, логику и факты**, без новых мыслей и обещаний. Берёт глубже, чем `--edit`. **Для «отредактируй и улучши, чтобы читалось лучше».**
- **Своя задача (`--instruction "…"`)** — любая инструкция: «напиши статью по этому плану», «сократи вдвое». Так используется способность агента писать по скелету.
- **Без флагов** — текст уходит как есть, агент решает сам (обычно расширяет в статью). Применяй осознанно.

Шкала вмешательства: `--edit` < `--correct` < `--instruction`/без флагов.

## Когда применять

- «Вычитать / поправить язык» → `--edit`.
- «Отредактировать, можно менять формулировки, но не смысл» → `--correct`.
- «Написать/развернуть по плану силами Яндекса» → `--instruction`.

Это **языковой/редакторский проход**, а не смена тона. За фирменный голос отвечает скилл `iiko-copywriting`: им пишут и переписывают, а `yandex-editor` запускают после. Не прогоняй через него куски, где формулировка важнее грамматики (заголовки-слоганы, CTA), без перепроверки.

> ⚠️ В `--correct` агент свободнее и может незаметно сдвинуть термины (на тесте «производства готовой еды» → «предприятия общепита» — это разные вещи). После коррекции обязательно сверь термины, бренд-нейминг и факты с оригиналом.

## Конфигурация (ключ и параметры)

Всё берётся из переменных окружения (в контейнере бота они уже заданы) или из файла `.env` в корне репозитория при локальном запуске. Нужны три переменные, в скрипте значений по умолчанию нет:

```
YANDEX_API_KEY=...       # ключ API
YANDEX_PROJECT_ID=...    # id каталога Яндекс Облака
YANDEX_PROMPT_ID=...     # id сохранённого промпта агента-редактора
```

Необязательная: `YANDEX_BASE_URL` (по умолчанию `https://ai.api.cloud.yandex.net/v1`).

Проверить, что ключ на месте (без вывода значения):

```bash
grep -qE '^YANDEX_API_KEY=.+' .env && echo "ключ есть" || echo "нет YANDEX_API_KEY"
```

Если ключа нет — попроси пользователя добавить строку `YANDEX_API_KEY=...` в этот файл (через редактор или `!`-командой). **Сам ключ в чат не выводи.**

## Как запускать

Скрипт без внешних зависимостей (только stdlib Python 3). Читает текст из файла или stdin, печатает отредактированный вариант в stdout или в файл.

```bash
# ВЫЧИТКА языка (минимально) → в новый файл, исходник не трогаем
python3 .claude/skills/yandex-editor/scripts/yandex_edit.py --edit --file article.md --out article.edited.md

# КОРРЕКЦИЯ (можно менять формулировки, смысл сохраняется)
python3 .claude/skills/yandex-editor/scripts/yandex_edit.py --correct --file article.md --out article.fixed.md

# вычитка из stdin → stdout
echo "текст" | python3 .claude/skills/yandex-editor/scripts/yandex_edit.py --edit

# НАПИСАТЬ ПО СКЕЛЕТУ / другая задача
python3 .claude/skills/yandex-editor/scripts/yandex_edit.py --instruction "Напиши статью по этому плану" --file outline.md
```

## Рабочий процесс

1. **Возьми текст.** От пользователя или из файла статьи.
2. **Отправь только содержательный текст.** Для страниц сайта не гоняй через редактор служебное: YAML-frontmatter, пометки `🔲 ГЭП`, внутренние `⚠️` нюансы, таблицы реквизитов. Передавай абзацы и заголовки контента.
3. **Запусти скрипт**, сохраняя результат отдельно (`--out` или во временный файл), чтобы сравнить с оригиналом.
4. **Покажи изменения.** Сравни до/после, отметь правки. Не подменяй исходник вслепую — дай пользователю принять результат (или примени правки осознанно, сверяясь со смыслом и бренд-правилами из `knowledge/iiko.md`).
5. **Сохрани**, если результат принят.

## Ограничения

- Длинные тексты режь на разумные части (раздел/несколько абзацев), если ответ обрывается или упирается в таймаут (`--timeout`).
- Редактор может тронуть термины и имена собственные — после прогона проверь бренд-нейминг и фактуру (числа, реквизиты), верни как было при расхождении.
- Ошибки API скрипт печатает в stderr с кодом — по ним понятно, что не так (нет ключа, сеть, неверный prompt id).
