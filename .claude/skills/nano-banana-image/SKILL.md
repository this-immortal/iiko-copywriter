# Генерация изображений через Nano Banana 2 (Gemini API)

Этот скилл позволяет обращаться к Google Gemini API, генерировать изображение моделью **Nano Banana 2** (`gemini-3.1-flash-image-preview`) и сохранять результат в PNG-файл на диск. Дальше файл можно вставлять в статью, документ Word, презентацию, PDF — куда угодно.

**Когда применять:** как только нужна сгенерированная иллюстрация. В том числе проактивно — если ты пишешь статью/гайд и хорошая картинка усилит материал, сгенерируй её через этот скилл и встрой в результат.

## Что нужно для работы

Нужен ключ Gemini API. Скрипт ищет его в таком порядке:

1. переменная окружения `GEMINI_API_KEY` (в контейнере бота она уже задана);
2. файл, указанный в `--env-file`;
3. файл `.env` в рабочем каталоге (при локальном запуске это корень репозитория).

Если ключ нигде не найден — **не придумывай ключ и не вставляй его в код**. Сообщи пользователю, что для генерации нужен Gemini API key в `.env` (получить можно на https://aistudio.google.com/apikey). Ключ платный для Nano Banana 2.

## Как сгенерировать изображение (основной путь)

Используй готовый скрипт `scripts/generate_image.py`. Он делает один запрос к Gemini, достаёт картинку из ответа и пишет PNG.

```bash
python3 .claude/skills/nano-banana-image/scripts/generate_image.py \
  --prompt "A photorealistic wide-angle shot of a cozy specialty coffee bar, warm morning light, shallow depth of field" \
  --out <каталог результатов>/coffee_bar.png \
  --aspect-ratio 16:9 \
  --size 2K
```

Параметры:
- `--prompt` (обязательный) — текстовое описание картинки. Чем подробнее, тем лучше (см. «Как писать промпт»).
- `--out` (обязательный) — куда сохранить PNG. Клади в каталог результатов текущего запроса (путь в служебной приписке).
- `--aspect-ratio` — соотношение сторон: `1:1`, `16:9`, `9:16`, `4:3`, `3:2`, `5:4`, и ультраширокие `4:1`, `1:4`, `8:1`, `1:8`. По умолчанию `1:1`.
- `--size` — разрешение: `512px`, `1K`, `2K`, `4K` (заглавная `K` обязательна). По умолчанию `1K`. Для иллюстраций в статье обычно хватает `1K`–`2K`.
- `--input` (можно повторять) — путь к входному изображению для редактирования / композиции (до 14 штук). См. «Редактирование».
- `--search` — добавить флаг, чтобы модель использовала Google Search для актуальных данных (погода, события, факты).
- `--env-file` — путь к `.env`-файлу с ключом, если он не в переменной окружения.

Скрипт печатает путь к сохранённому файлу. После генерации **проверь, что файл создан** (`ls -la <out>`), прежде чем встраивать его дальше.

## Редактирование и композиция

Та же модель умеет редактировать переданные картинки и собирать новые из нескольких. Передай один или несколько `--input`:

```bash
# добавить элемент / изменить фрагмент / сменить стиль
python3 .claude/skills/nano-banana-image/scripts/generate_image.py \
  --prompt "Используя это фото, добавь небольшую вязаную шапку. Остальное оставь без изменений." \
  --input <каталог входящих>/cat.png \
  --out <каталог результатов>/cat_hat.png

# композиция из нескольких изображений
python3 .claude/skills/nano-banana-image/scripts/generate_image.py \
  --prompt "Возьми платье с первого изображения и надень его на человека со второго. Реалистичный полноростовой кадр." \
  --input <каталог входящих>/dress.png \
  --input <каталог входящих>/model.png \
  --out <каталог результатов>/result.png
```

## Как писать промпт (это сильно влияет на качество)

Описывай **сцену**, а не ключевые слова. Чем конкретнее, тем больше контроля. Полезные оси описания: тип кадра и ракурс, субъект и детали, окружение, свет, стиль/медиум, настроение.

Рабочие шаблоны под типовые задачи:

- **Фотореализм:** `A photorealistic [тип кадра] of [субъект с деталями] in [окружение]. [Описание света]. Shot from [ракурс] with a [тип объектива].`
- **Иллюстрация / стикер:** `A [стиль] illustration of [субъект], [действие]. [Визуальные качества: чёткие контуры, cel-shading…], [цвет/фон].`
- **Текст в картинке (логотип, обложка):** `Create a [тип] for [бренд] with the text "[точный текст]" in a [описание шрифта]. [Стиль], [цветовая схема].` Nano Banana 2 хорошо рендерит читаемый текст.
- **Продуктовый мокап:** `A high-resolution, studio-lit product photograph of [продукт] on [поверхность]. [Схема света]. [Ракурс]. Ultra-realistic, sharp focus on [деталь].`
- **Минимализм с местом под текст:** `A minimalist composition featuring a single [субъект] in the [угол] of the frame. Vast empty [цвет] background, significant negative space. Soft lighting.` — удобно, когда поверх картинки ляжет заголовок.

Советы:
- Для иллюстрации в статью бери соотношение под вёрстку (часто `16:9` для шапки, `1:1` или `4:3` внутри текста) и оставляй негативное пространство, если планируется текст поверх.
- Промпт можно писать по-русски или по-английски; для точного рендеринга английского текста на картинке формулируй сам текст так, как он должен появиться.
- Все изображения содержат невидимый водяной знак SynthID — это нормально.

## Встраивание результата в материал

После того как PNG сохранён, используй его по назначению:
- **Markdown/HTML-статья:** вставь через `![alt](путь)` или `<img>`.
- **Word (.docx), презентация (.pptx), PDF:** сначала прочитай соответствующий SKILL (docx / pptx / pdf), затем вставь изображение по его инструкции.
- Файл из каталога результатов бот отправит в чат сам.

## Технические детали и устранение проблем

- Модель: `gemini-3.1-flash-image-preview` (Nano Banana 2). Для максимального качества/сложного текста существует `gemini-3-pro-image-preview` (Nano Banana Pro) — можно подменить через `--model`, но он дороже и медленнее.
- Скрипт ходит на стабильный эндпоинт `generateContent` REST API. Google также предлагает новый Interactions API (beta) — для этого скилла он не нужен.
- Сеть к `generativelanguage.googleapis.com` должна быть разрешена. Если запрос падает с сетевой ошибкой, скажи пользователю, что нужно добавить домен в настройках сети.
- Типичные ошибки: `401/403` — неверный/неактивный ключ; `429` — превышен лимит/нет биллинга; пустой ответ без картинки — сработал фильтр безопасности, переформулируй промпт.
- Не генерируй изображения, нарушающие правила: реальные узнаваемые люди в вводящем в заблуждение контексте, защищённые персонажи/бренды, оскорбительный или небезопасный контент.
